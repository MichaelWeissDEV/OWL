# Importing skills

`owl add` is the one way into your library. It **discovers** candidates, **parses** and **normalises**
them, **validates** them and only then **stores** them – these steps are separate, and each import
reports what it would do.

```console
$ owl add SOURCE... [--allow-incomplete | --interactive] [--dry-run] [--author A] [--skill NAME]
                    [--ref REF] [--subdir PATH] [--no-recursive] [--json] [--yes]
```

## What can be a source

| Source | Notes |
| --- | --- |
| a skill directory | one `SKILL.md` and its bundled files |
| a directory tree / monorepo | searched recursively (default); every directory with a `SKILL.md` is a skill and its sub-directories belong to it |
| a local git repository | the current commit is recorded |
| a git URL (`https://`, `ssh://`, `git@…`, `file://`) | shallow clone into a temporary directory; `--ref` branch/tag, `--subdir` |
| a `.zip` archive | extracted safely (see below) |
| a single `.md` file | becomes a candidate (`skill-file` if it has `name` and `description`, otherwise `markdown`) |
| prompt/command markdown | `*.md` in directories named `commands`, `command` or `prompts` are found as `markdown` candidates |

Several sources can be given at once. `owl scan [SOURCE...]` runs only the discovery and prints a table
(or `--json`) without importing anything; without arguments it scans the sources registered with
`owl source add`.

### What discovery reports

Each candidate carries: original path, position inside the source, format, name, author, description,
version, tags, topics, the full text, bundled files, content hash, **status** (`valid`, `incomplete`,
`invalid`, `rejected`), concrete problems and warnings, the source, and the git commit when known.

## Strategies

| Mode | Option | Behaviour |
| --- | --- | --- |
| **Strict** (default) | – | Only valid skills are stored. Everything else is reported and skipped |
| **Defaults** | `--allow-incomplete` | Missing metadata gets defaults; still-invalid input becomes a local **draft** |
| **Interactive** | `--interactive` / `-i` | Valid skills are imported without questions; for every *incomplete* skill you decide |
| **Dry run** | `--dry-run` | Shows the plan (add / update / unchanged / skip / draft / reject); changes nothing |

```console
$ owl add ./skills --dry-run
┏━━━━━━━━┳━━━━━━━━━━━━━━━━━━━┳━━━━━━━━━━━━━━━━┳━━━━━━━━━━━━━━━━━━━━━━━━━┓
┃ Action ┃ Skill             ┃ Source         ┃ Note                    ┃
│ add    │ alice/good        │ good           │                         │
│ skip   │ no-frontmatter    │ no-frontmatter │ incomplete: Missing ... │
│ draft  │ broken-yaml       │ broken-yaml    │ Invalid YAML: ...       │
```

### Defaults

| Field | Default |
| --- | --- |
| name | the frontmatter name if valid, else a slug of the directory / file name |
| author | the author in the source, else `owl init --author`, else `local` |
| version | `0.0.0` |
| description | the frontmatter value, else the first paragraph of the text, else *"Skill imported from … (description generated by OWL)"* |
| tags / topics | those of the source, else empty |

Every generated field is recorded in the skill's metadata (`owl_generated`) so it stays visible.
The stored copy gets a valid frontmatter (name, description) while the body is kept; **your source
files are never modified**.

### Interactive import

```console
$ owl add ./messy --interactive

Incomplete skill 1/2: packages/b/no-frontmatter (agent-skills)
  - Missing YAML frontmatter
  suggested: name=no-frontmatter author=me version=0.0.0
  description: Does something useful.
[A]ccept defaults / [e]dit values / [s]kip / [all] accept remaining / [q]uit [a]:
```

- **Enter** accepts the suggestion; `e` asks for each field (Enter keeps the default); `s` skips;
  `all` accepts the defaults for all remaining skills; `q` aborts without importing anything.
- Before anything is written you get the plan table and a confirmation (`--yes` skips it). If no skill
  was incomplete there are no questions at all, so importing hundreds of valid skills stays
  non-interactive.

## What `--allow-incomplete` does *not* relax

Security and integrity rules are never disabled: path traversal, absolute or odd paths, symlinks
(never followed), oversized files and skills, reserved file names and malformed archives are
**rejected**, not repaired. Content that defaults cannot fix – for example frontmatter with broken YAML –
is kept as a draft rather than stored as a valid skill ({doc}`local-library`).

## Archives

Zip files are extracted with strict checks before anything is read: every member path must be a safe
relative path, symbolic links are refused, and the file count (5,000) and expanded size (100 MiB) are
limited. A malicious archive stops the whole import; nothing is written outside a temporary directory.

## Already stored skills

An identical skill is `unchanged`; a changed skill with the same `author/name` is an `update`. In
git-based libraries and registries two different authors cannot share a skill **name** (the
directory is `skills/<name>/`) – such a collision is reported as `failed` and nothing is overwritten.

## Fixing things afterwards

`owl validate [REF|PATH] [--all]`, `owl metadata …`, `owl edit REF`, `owl drafts …` – see
{doc}`local-library`.
