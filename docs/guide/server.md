# Server mode

`owl serve` exposes a store over an HTTP/JSON API so that clients can search, pull and push. It needs
the `server` extra.

```console
$ pip install "owl[server]"
$ owl serve
owl server on http://127.0.0.1:8765  backend=sqlite  writes=disabled  reads=open
```

## Options

| Option | Env var | Default | Meaning |
| --- | --- | --- | --- |
| `--host` | | `127.0.0.1` | interface to bind. Use `0.0.0.0` to accept remote connections |
| `--port` | | `8765` | TCP port |
| `--db-url` | `OWL_DB_URL` | the configured store | SQLite path, `postgresql://` URL |
| `--token` | `OWL_SERVER_TOKEN` | none | write token; without it the server is **read-only** |
| `--private` | | off | require the token for reads too (needs a token) |

Prefer environment variables for secrets – command-line arguments are visible in `ps` and in shell
history.

## What is served

- With `--db-url` / `OWL_DB_URL`: that database (SQLite file path or PostgreSQL URL).
- Otherwise the store from `owl init` – SQLite, PostgreSQL **or a git working copy**.

A git-backed server caches the directory in memory at start-up and after its own writes; restart it
(or push through the API) after editing files manually.

## Access control

| Mode | Reads | Writes (`PUT`, `DELETE`) |
| --- | --- | --- |
| no token (default) | open | **disabled** (HTTP 403) |
| `--token T` | open | `Authorization: Bearer T` |
| `--token T --private` | token required | token required |

Tokens are compared with `secrets.compare_digest`. There is a single shared token; per-user
accounts are not implemented (see {doc}`../roadmap`). Terminate TLS in a reverse proxy when the
server is reachable beyond localhost ({doc}`../operations/reverse-proxy`).

`/api/v1/health` is always open (for load balancer checks).

## Web page and API docs

- `GET /` – a small read-only HTML page with a search box (HTML-escaped; no JavaScript).
- `GET /docs` – interactive OpenAPI documentation generated by FastAPI; `GET /openapi.json` is the
  machine readable schema.
- The full API is described in {doc}`../reference/http-api`.

## Several servers

Nothing prevents you from running as many servers as you like – each with its own database, token and
audience (public, team, personal). Clients register all of them with `owl remote add` and can search
all at once with `owl search --all`. See {doc}`../tutorials/multi-server`.

## Validation on write

`PUT` validates the uploaded skill exactly like the CLI does: name/author format, description,
reserved file names, safe relative file paths, size limit. The URL's `author/name` must equal the
body's. Invalid uploads receive HTTP 422 with a `detail` message; nothing is stored.
